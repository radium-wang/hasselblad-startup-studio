# Windows RGB 开机画面迭代

当前本地 Mac / Windows `0.3.0-rgb-preview.5` 将相同彩色适配层用于两端。Mac 使用原生三栏界面，Windows 以其布局为准；两端都恢复原版基础裁剪与导入限制，取消 preview.2–4 的高清自动缩图、四边手柄、滚轮和单独绘制工具。首次整图选框内拖动会新建裁剪框；进入 Windows 裁剪模式后编辑区会滚入小窗口可见范围。导出按钮位于中间相机画布旁，导出当前裁剪后的原尺寸图片，不包含画布黑边。ARM64 RGB 41 项模拟、Mac 两架构各 75 项及 Windows 231 项离线检查通过；没有真实相机 RGB 冷启动或恢复验收。

以下为早期 Windows RGB 预览版的历史记录。

Windows `0.3.0-rgb-preview.4`（本地测试包“哈苏win启动RGB 0.1.1”）：裁切框四边可独立拖动，右上角新增一次性“绘制画框”工具，可从旧框内部或外部重新画框，完成后返回调整模式；四边及四角在工具选中时仍可调整。255 项离线回归通过，新增 20 项交互检查覆盖整条边、对边固定、越界、四个画框方向、无拖动及 Esc 取消和模式切换。四种原生 Windows 窗口检查通过，确认右上角按钮、固定预览、滑条分离和底部按钮可见。相机端实现沿用上一版，未访问实体相机。

preview.3 的布局继续保留：成品预览放大并固定在左栏顶部，图片设置单独滚动，滚动条与菜单留出间隔。235 项离线回归及四种原生 Windows 布局检查通过，包含 1260×800／1080×640、成品／裁切和设置滚动到底部。

preview.4 再次运行五种基线的实际生成 shell，在临时桌面文件系统验证正常安装／换图／恢复、损坏备份保护、85 处安装与恢复中断及五种服务撤回失败，全部通过。服务、标签、Windows 权限与 Android ELF 加载使用替身或模拟，不能代替相机上的恢复验收。

preview.2 的高清图片处理继续保留：高清 PNG／JPEG 和 16-bit PNG 在软件内校正方向、按嵌入颜色信息转换到 sRGB、生成固定 1024×768 的 8-bit 灰度或 RGB 每通道 8-bit 成品。编辑工作图最长边 4096，保留高精度中间格式处理 16-bit PNG，最终缩图后才输出 8-bit；图片显示、鼠标裁切、导出和安装共用结果。原图不改写，编辑器在中间大区域，支持拖动、四角、滚轮与选框缩放。此次相机端载荷、恢复脚本及原厂备份没有改动，下面保留 preview.1 的相机端实现及证据。

preview.2 验证：带显式本地原库的 235 项离线检查通过；新增独立构造的 16-bit RGBA PNG、6000×4000 JPEG、透明度、成品尺寸／位深、原图保持和像素采样检查，以及实际 Avalonia 鼠标事件驱动的移动、四角、边界手柄、释放和滚轮检查。原生 Windows 成品／裁切两视图与底部按钮可见性通过，247 个发行文件和 ZIP 校验通过。相机载荷、历史恢复载荷、控制器及恢复脚本与 preview.1 逐字节一致；没有重新进行实体相机验收，也没有用桌面缩图测试代替硬件恢复测试。

`0.3.0-rgb-preview.1`，2026-10-15，本地 Windows 测试版。Mac 灰度应用保持原实现。新版尚未进行真实相机安装、恢复或冷启动视觉验收。

## 来源与实现

参考 radium-wang 大库固定提交 [09619505 的彩色 Logo 研究](https://github.com/radium-wang/Hasselblad-X-System-CIM-Firmware-Research-Feature-Extensions/blob/09619505fea52bf4043631305c7a4a39a2c5feb2/x2d/research/4.2.0/STARTUP-LOGO-REPLACEMENT.md)。其 250×250 彩图案例确认原厂灰度循环无法保留颜色，并经现场观察纠正红蓝顺序；该案例仅为短时 RAM 实验，没有持久安装或冷启动证据。本版不能借用旧实验宣称实机验收。

新增 `native/loader-rgb.S`，沿用独立模式 3、固定原库哈希与既有四处差异范围，不改原厂 H／大地图数组。旧 `native/loader.S` 原样保留，可重建与历史完整哈希一致的灰度适配层。原厂核心库仅从显式本地输入读取，另行生成候选；首次原库及属性备份保留，运行时配置与图片独立管理。

灰度协议版本 1 保持；版本 2 的同一 32 字节头承载 B、G、R、0 四字节像素，FNV-1a 覆盖全部数据，最大 3,145,728 字节。Windows 导入 PNG／JPEG 保留 RGB、透明度在黑底合成，支持原尺寸居中、裁剪和彩色 PNG 导出，也能显式转灰度。宽高仍不超过 1024×768。相机端检查当前画布、4 字节格式与 stride；格式、读取、校验或分配失败回原厂，成功与失败路径均释放资源。

“连接相机”“恢复原厂”“安装自定义画面”统一在右下角同一行，小窗口检查覆盖排列与可见性。

## 恢复与旧版

发行包必须保留独立的历史 `Resources/legacy/a2edfe28ad8dbf91ed19fb87526cc6eceb21ceb00a40347ee58e9afaec6929e0/adapter.json` 与 `patch.bin`。旧灰度安装可以识别、恢复，安装新版前须先恢复原厂，不能直接覆盖旧版本。

已有 `baseline.json`、`original-backend.so` 不因升级改写。新事务可以登记新版适配层，但首次原厂基线必须完全相同，新旧载荷都须是明确登记的版本；未知修改、跨相机记录、原库损坏与属性冲突继续拒绝覆盖。

恢复从机内原库副本生成并校验暂存库，再原子替换；原库副本、主机事务和机内恢复记录保留到内容／属性、原厂身份、实际加载分支及服务确认完成后才进入清理。任务、服务、通信或清理失败后记录保留；重新连接识别记录后恢复入口可用，不完整安装与异常服务状态禁止继续安装。主机首次备份在成功恢复后仍保留。

## 离线证据与限制

- 41 项实际 ARM64 指令模拟通过：灰度兼容、RGB 250×250／满画布／单像素、短读、通道、校验错误、分配失败、非 4 字节格式、stride 不足和 H／大地回退，逐字节 framebuffer 对比及堆／画布守卫。
- Windows 带本地固定原库的 220 项检查通过，零警告编译。涵盖五种机型／原键基线、安装／换图／恢复、旧灰度恢复后升级、首次备份不变、任务／服务／恢复中断／清理失败后重试、RGB 编解码／PNG／透明度、按钮布局与失败服务的恢复入口。设备与服务为替身，未访问 USB。
- 实际生成 shell 在 Windows 临时文件系统运行：5 种基线、85 个安装／恢复中断点和 5 种失败服务撤回后的重试通过；Android 加载器、显示服务、SELinux 和 Windows 权限为明确替身。只验收本地内容、事务顺序与故障分支，不能作为 Android 动态链接或真实服务证据。
- 175 项无厂商输入检查通过；原生 Windows 窗口与彩色预览通过。真实桌面把窗口高度限制在工作区时，界面按实际客户区重新布局，右下角三个按钮仍可见。247 个发行文件、依赖、许可证、历史恢复资料、清单和 ZIP 独立校验通过。

待验收：新版真实 X2D 的持久安装、完整关机再开机的色彩、连续换图、恢复、USB／电源中断、服务失败后的硬件恢复及 CFV／大地机。离线通过不代表硬件零风险，旧灰度版验收也不能代替本版。默认构建和测试不安装、恢复或重启真实相机。

## 重建

```sh
python tools/build_adapter.py /path/to/original/eagle-backend.so outputs/rgb-adapter --rgb
python tools/build_adapter.py /path/to/original/eagle-backend.so outputs/legacy-adapter
python CodeTests/check_loader.py /path/to/original/eagle-backend.so outputs/rgb-adapter
```

Windows 可通过 `--cc /path/to/zig.exe` 使用 Zig 0.13.0 的 Clang 汇编器，构建／模拟工具不进入运行包。Windows 打包同时指定 `--adapter outputs/rgb-adapter --legacy-adapter outputs/legacy-adapter`，其他参数见 [Windows 文档](WINDOWS.md)。运行带原库测试前将历史清单和补丁复制到当前资源的上述 `legacy` 子目录，测试程序不会从相机获取输入。
